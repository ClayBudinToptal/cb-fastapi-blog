alembic - db migrations tracker - works well with sqlalchemy (same author)
	saves migrations (db changes) in files - can upgrade and downgrade (roll back)
	like version control for dbs
> uv add alembic
Initialize to run aync and save in alembic/ folder - alembic.ini settings file
> uv run alembic init -t async alembic/
Edit alembic.ini and alembic/env.py - see *change* comments

Create the initial migration - creates migration file but doesn't apply to db
> uv run alembic revision --autogenerate -m "Initial schema"
This generated an InterfaceError - (psycopg.InterfaceError) Psycopg cannot use the 'ProactorEventLoop' to run in async mode.
Fixed by changing event loop policy (bc we are on Windows) adding:
import sys
if sys.platform == "win32":
	asyncio.set_event_loop_policy(asyncio.WindowsSelectorEventLoopPolicy())
to env.py - will probably need to add to main.py as well

In PostgreSQL all tables are in a public schema
This will clear the database by dropping (deleting) the public schema and re-creating it:
> psql -U bloguser -d blog -c 'DROP SCHEMA public CASCADE; CREATE SCHEMA public;'
Now can delete migration file and do alembic initial schema again (it worked the first time, but to illustrate)
Migration file is .py file that contains all the db commands to create (or delete) the db to update it

Apply all the migrations up to the latest version (head) run the migration scripts in order:
> uv run alembic upgrade head

Verify:
> psql blog -U bloguser
blog=> \dt

blog=> \q

Dockerfile - recipe that tells Docker how to build container Image
	Builder stage and production stage
	allows for copying only necessary files between stages to keep Image as small as possible
Image - the build result of the recipe
Container - running instance of an Image

.dockerignore file - files to ignore when copying into Image

Docker containers are stateless - don't retain any data besides Image
Can't run PostgreSQL inside container - would get wiped out every time
Use online PostgreSQL db - Neon - neon.com - popular, has free tier
